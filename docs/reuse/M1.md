# M1 provenance

File-level provenance for the task substrate. Evo-Bench code is **imported from the
submodule** (`third_party/evo-bench`, `e1dc9386…`, Apache-2.0) as the uv path dependency
`evo-bench`; nothing from it is copied into `src/`. Claw-Eval is an **external checkout**
(`external/claw-eval`, commit `d3f02d49…`, gitignored, prepared by Evo-Bench's own
`scripts/setup_claw_eval.sh`); it is executed, never copied or redistributed.

## Imported and called (not copied)

| `ahd/tasks/evobench.py` | `evobench.evaluation.tasks.load_suite` | canonical suite JSON, `_asset_files_abs` resolution |

Dependency note: Evo-Bench pins `openai<3`; `pyproject.toml` carries
`[tool.uv] override-dependencies = ["openai>=3"]`. The override is verified by
`tests/integration/test_evobench_live.py::test_evobench_client_shape_under_openai3`, which
makes one real call through `OpenAICompatibleClient` and asserts the fields the scorer reads
(`choices[0].message.content`, `usage` via `usage_to_dict`). The manifest records
`environment.openai_version`.

## Judge routing (owner decision 2 and 4)

All judge calls are `ChatRequest`s with `arm="judge"`, model `deepseek-v4-pro`, temperature
0, cache on, and `cache_scope="artifact:<sha256>"` where the hash covers the final answer,
everything under `outputs/`, and the trajectory file. Evo-Bench's scorer receives an
`AhdJudgeClient` as `judge_client`. For Claw-Eval, whose grader constructs its own judge,
`patched_claw_judge` replaces exactly one attribute, `claw_eval.graders.llm_judge.OpenAI`,
with a shim exposing `chat.completions.create`; Claw's `LLMJudge.__init__`, retry loop,
parsing and call log run unchanged. Multimodal judge content is refused, which makes
Evo-Bench's GDPval judge take its own text-only fallback and record
`image_grading.used = false`.
