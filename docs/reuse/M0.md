# M0 provenance

What was borrowed from which reference repo, file by file, and what was written fresh.
Shas and licenses are in `THIRD_PARTY_NOTICES.md`; the survey that drove these choices is
`survey.md` in this directory. Every listed file carries the same information in its module
docstring.

## Patterns followed without copying code

| ahd file | Pattern | From |
|---|---|---|
| `src/ahd/errors.py` | infrastructure vs terminated split | VeRO `evaluation/exceptions.py` |
| `src/ahd/settings.py` | mask first/last four characters | agentic-harness-engineering `evolve.py:48-54` |
| `src/ahd/core/context.py` | run id = UTC timestamp + short hex | Evo-Bench `new_run_dir` |
| `src/ahd/core/manifest.py` | manifest field set | Evo-Bench `run_manifest.json`, VeRO `SessionManifest`, AutoSaddler `manifest.json` |
| `src/ahd/llm/types.py` | usage field names incl. `prompt_cache_hit_tokens` | Evo-Bench `usage_to_dict` |
| `src/ahd/llm/ledger.py` | column names, row-per-event | VeRO gateway request log, AutoSaddler `PaidWorkLedger` |
| `src/ahd/llm/deepseek.py` | `max_retries=0` on the SDK client | VeRO `labeling/client.py` |
| `src/ahd/llm/fake.py` | in-tree fake provider | AutoSaddler `providers/fake.py` |

## Written fresh (no reference source)

`src/ahd/__init__.py`, `errors.py`, `settings.py`, `logs.py`, `cli.py`,
`core/context.py`, `core/manifest.py`, `llm/types.py`, `llm/provider.py`,
`llm/pricing.py`, `llm/ledger.py`, `llm/deepseek.py`, `llm/fake.py`, all of `tests/`,
`configs/*`, `Makefile`, `.pre-commit-config.yaml`, `.github/workflows/ci.yml`.

Of these, the survey (section 5) identified the following as things no reference does at
all: JSON log formatter, git sha and dirty flag in the manifest, `integration` pytest marker,
pricing table with `pricing_version`, `mypy --strict`, pre-commit.

## Not used

`rethinking-harness-evolution`: nothing (no LICENSE file; see `permissions/README.md`).
`microsoft/AgentRx`, `ulab-uiuc/AgentDebug`: nothing in M0; both are trajectory-analysis
codebases whose relevance starts with the diagnostic modules.
