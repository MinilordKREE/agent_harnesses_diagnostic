## Decisions applied (owner, M2 addendum)

- Policy tokens post hoc per step from `trajectory.json`, one `policy` ledger row per rollout,
  reconciled against `metadata.json`; mismatch is `InfraError(kind="usage_mismatch")`.
  `api_base` stays a settable `PolicyModelSpec` field. The worker's SDK client retries twice
  (`openai.DEFAULT_MAX_RETRIES == 2`, recorded as `environment.policy_sdk_max_retries`).
- No web freeze in M2. Serper calls are counted from shell commands, `approximate: true`.
  `web_snapshot_id` remains reserved.
- Reference mode: frozen prompt block, attempt loop up to `reference_max_attempts` (default 5)
  stopping at the first pass; `ReferenceRecord.verified = "pending"` for M3.
- `MOCK_TODAY`: study-wide `run.mock_today` injected into `claw_public` only when the task's
  own value is null; recorded in the manifest via `run_spec`.
- Snapshot validation refuses: budget drift, `harness.json:tools` vs `TOOL_SCHEMAS` mismatch,
  imports outside stdlib + tree + the two Evo-Bench modules.
- Scores for normal mode are written after all replicates of a task complete.
- Found by the first live run: Evo-Bench's Claw grader resolves the task directory through
  `claw_runtime.claw_repo_root()`, which reads `EVOBENCH_CLAW_REPO` from the *host* process
  (scorer.py:1107-1109), while the runner had only set it for the worker. `ahd.tasks.scorer`
  now sets and restores that variable around Claw grading (`claw_repo_env`), so scoring works
  without a process-wide environment change.

## M2.1 (bounded parallelism and resume)

No reference source. `Runner.run` executes (task, replicate) lanes on a `ThreadPoolExecutor`
bounded by `RunSpec.workers`; Evo-Bench's per-rollout PID-tagged port leases
(`claw_runtime.py:91-126`) make concurrent Claw rollouts safe. Thread safety added:
`Ledger.append` under a lock; `patched_claw_judge` installs the module patch once (refcounted)
and binds the per-task judge in a context variable; `claw_repo_env` is refcounted. Resume:
`done.json` per attempt, `rollout_uid` on ledger rows (v4), `load_run_context` from the
manifest, `ahd run resume <run_id> [--workers N]`.
